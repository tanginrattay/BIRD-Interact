# 比较结论、典型轨迹与下一步

本批是四条开发/诊断任务、四组Prompt、每组每任务三次的探索性对照。48/48完整完成，0任务级错误，服务日志未发现LLM异常。均值和样本标准差、每任务三次统计、三轮四任务均值见 [README](README.md)。不报告统计显著性，不将观察结果解释为论文创新。

## 1. A 是否真正降低知识成本

在这组样本中支持“平均知识成本下降”：每run定义查询成本从 Baseline **3.625±1.448** 降至 A **3.042±1.499** bird-coins，下降16.09%；包含每次0.5的知识名称查询后，从4.125降至3.542，下降14.14%。这是按预算实际扣费核验的结果。

代价与局限同时存在：A全量查询均值0.75次，高于Baseline0.50次；返回的不同定义从28.42增加到39.83；条目级相关性宏平均从0.212降到0.113。精确重复调用由0.50升至0.67。它省的是工具价格，没有同时改善重复、上下文噪声与成功率。P1均为4/12，P2从4/12降为3/12，reward从0.333降为0.308；剩余预算反而从0.625降至0.125，知识省钱不能直接等同于总预算省钱。

任务差异很大：credit的平均知识成本2.333→1.500，cybermarket 3.500→2.167，polar 4.833→4.167，但virtual 3.833→4.333。A在credit第二、三次采用了直接全量，另一些任务仍先连续单项再全量。日志不能证实模型内部确实做了预估，结论只依据实际行为。

## 2. B 是否比 A 减少重复和低价值检索

部分支持。精确重复调用均值 **0.667→0.333**；含精确重复的语义重复调用并集 **0.750→0.333**。相关性宏平均 **0.113→0.263**，不同定义数量 **39.83→20.67**，全量检索由0.75降至0.333次。

但跨来源/不同ID的额外语义重复，两组都只有1次，均值同为0.083；无新增相关信息的调用反而从 **3.917升至4.167**，知识调用数从5.333升至5.750。总知识成本同为3.042；P1-only成本B略低（3.000 vs 3.042），差异很小。B的P1为3/12，低于A的4/12，P2均3/12。不能据此声称“状态感知全面改善策略”。

[baseline_r2 cybermarket](task_cards/baseline_r2__cybermarket_1.md) 的ask7已给出完整洗钱条件，query8又获取同一KB23；[B_r1 cybermarket](task_cards/B_r1__cybermarket_1.md) 的ask5已给出这些条件，bulk7又返回同样信息。这些是有先前证据的跨来源重复，不把其他不相关指标误称为语义等价。

B没有新增程序状态字段；模型是否真的持续维护了内部信息状态不可由日志直接证实。这里只评价检索结果和行为。

## 3. C 是否更早识别用户语义歧义

没有稳定支持。首次ask前的定义查询均值为 **B 5.500±2.195，C 5.333±2.229**，只少0.167次；首次ask工具序号为 **9.000 vs 8.917**。virtual均6次，cybermarket均2.667次；credit和polar各只少0.333次。

C仍多次先查询相近概念：C_r2 polar在9次单项查询后才ask；C_r2 credit重复查询Digital Channel Opportunity。C_r1服务进程的环境变量和每批Prompt哈希已核实，C追加策略确实加载；不能将未执行预期策略解释为文件未生效。

按固定信息需求的离线标注，整体歧义解决率B为0.783，C为0.733；用户语义子集B为0.597，C为0.542。这里的“解决”要求可见证据充分，部分解决不计完整解决。例如cybermarket只确认降序、未说明top-N与全部结果范围，就保留为部分解决；即便最终SQL恰好正确也不倒推已明确澄清。

## 4. C 是否减少无效探索而不增加不必要询问

仅有弱的描述性支持。知识成本 **3.042→2.917**（下降4.11%；P1-only 3.000→2.833），无新增相关信息调用 **4.167→4.000**，相关性宏平均 **0.263→0.301**。精确重复和包含精确重复的语义重复调用均值仍为0.333，没有进一步下降。

Ask总数 **B20、C21**，每run1.667→1.750；按严格标准，四组都未标出整次完全不必要的ask。若把含已知内容的复合问题也纳入上界，Baseline为4/23，A为2/22，B为2/20，C为1/21。这不证明询问最优；它只说明这批轨迹没有观察到明显增多的完全无必要提问。

C的P1为5/12、P2为4/12，reward **0.392±0.491**；B为3/12、3/12、0.250±0.452。优势主要出现在virtual，不能声称是更早询问造成，也不能用三个重复声称显著。

## 5. 四条任务的典型变化

### credit_11

四组P1均0/3。A的直接全量降低了工具成本，B/C仍有旁支检索。多数运行获得CES、digital-first和高参与阈值，但输出百分比的分母、季度表示和SQL实现仍不稳定。

[Baseline r1](task_cards/baseline_r1__credit_11.md) 的ask8给出正确digital-first和CES>0.7，ask15给出两个分母；最后submit19仍用EXTRACT(QUARTER)丢失年份，把比例乘100，并将digital-first比例重复到两个状态组。SQL另有LEAST封顶，与知识库说明一致但与参考SQL不同。多个问题同时存在，不能把失败只归因于封顶差异。

[ A_r2 ](task_cards/A_r2__credit_11.md) 只用了1次全量，却花了3次ask；中途Simulator错误解释为整个季度的比例，最后一次回答才纠正。成本、信息覆盖、SQL采用、Simulator可靠性需要分开评价。

### virtual_1

P1：Baseline2/3、A2/3、B1/3、C3/3；P2分别2/3、2/3、1/3、2/3。C本样本P1较好，但首问前仍有6次定义查询，并未更早。

[B_r1](task_cards/B_r1__virtual_1.md) 已在KB49取得spendusd<100，并从ask9取得GIQ公式和Free/Basic映射，最后submit18仍漏掉spendusd<100。这是“已经获得但未正确采用”，不是没有知识。

[C_r1](task_cards/C_r1__virtual_1.md) 分别询问gift score和lower-tier，最终只在预算不足的免费退出提交中通过P1，无法继续P2。需要保留阶段预算这一代价。

[Baseline r3](task_cards/baseline_r3__virtual_1.md) 的三次ask来自连续漏答；不能简单按次数判为冗余。

### polar_M_4

四组P1均0/3，是本批最明显的失败下限。平均知识调用8.667/7.333/8.333/8.000；所有组都持续追查被隐藏的WRMI公式。即使获得正确公式，也常未澄清“summary”要求创建命名视图。

[A_r1](task_cards/A_r1__polar_M_4.md) 在ask19得到三列与非空范围后，submit20仍是SELECT；参考要求CREATE OR REPLACE VIEW water_management_view。必要对象名没有从可见信息中确定，不能要求模型凭空知道。

[C_r1](task_cards/C_r1__polar_M_4.md) ask10正确，ask12却被Simulator建议额外除以100，最终SQL采用了错误规范化；它同时还有SELECT而非视图、额外equipmenttype等问题。这个Simulator错误是贡献因素，不是唯一失败原因。

### cybermarket_1

四组P1均2/3；P2分别2/3、1/3、2/3、2/3。知识成本3.500/2.167/2.000/2.000，说明任务并非依靠更多知识调用才能通过。

[C_r1](task_cards/C_r1__cybermarket_1.md) 与 [C_r3](task_cards/C_r3__cybermarket_1.md) 都有3次P1定义查询、成本1.5、2次P1询问。r1第二问只问TCR公式，没有得到洗钱条件，失败；r3第二问同时问公式与suspicious阈值，获得完整四项条件并通过P1/P2。这是可核查的问句内容差异，不是两条轨迹就能建立的因果估计。

## 6. 查询减少但覆盖或成功下降的情况

存在具体案例，也存在组均值上的代价：

- [A_r1 cybermarket](task_cards/A_r1__cybermarket_1.md) 知识成本1.0，低于Baseline同轮3.5，但只取得TCR公式，没有KB23洗钱判据，覆盖0.5、P1失败；最终SQL误用了TAS>75/Crypto_B/escrow/routing过滤。
- [B_r3 cybermarket](task_cards/B_r3__cybermarket_1.md) 成本2.0，低于B_r1的2.5，同样缺少洗钱过滤，覆盖由1降为0.5，P1由通过变失败。
- A组平均成本下降，但P2由Baseline4/12降至3/12。B相对A成本相同，P1却由4/12降至3/12。
- C最终可靠覆盖0.917，低于B的0.958；差别来自C_r1 polar的未解决冲突回答。若只统计“曾经见过正确内容”，四组均为0.958。应把这个覆盖下降与纯检索不足区分开，而不是把它当成C必然漏检知识。

## 假设与最值得继续的问题

- 成本规则能降低这批任务的平均知识支出：得到描述性支持，但不是所有任务都省，也没有保证更高成功率。
- 状态提示能减少重复和低相关检索：精确重复、返回条目噪声有所改善；无新增相关调用未下降，成功率未改善，只有部分支持。
- 歧义提示能稳定更早询问：本批不支持；均值差很小，语义信息需求覆盖也未提高。
- 歧义提示能兼顾探索、询问与成功：C观察得分较高、成本略低、没有明显增加完全不必要询问，但不能建立稳健因果结论。

下一轮最值得研究的是 **澄清问题对当前缺口的覆盖与策略执行率**：用Prompt明确核对“指标公式、筛选判据、输出/交付形式”是否都已确定，并做规则位置和优先级的对照。cybermarket相同成本但不同问句内容的案例尤其适合检验。继续限制在Prompt实验，不据此直接实现分类器或新架构。若还要比较状态提示的独立收益，应补充长度匹配的提示控制，并使用未参与本轮诊断的任务。

## 解释限制和审查记录

每任务每条件只有3次，任务选择不是独立泛化测试；C示例中包含被测任务的用语，不能声称跨任务泛化。Prompt长度随策略变化，原日志缺失usage，不能排除输入长度/注意力影响。模型为官方别名而非不可变快照；全批设置相同，但没有服务端版本锁定证明。

原始Prompt“先探索”与追加规则的更早澄清优先级可能影响执行；本轮按约定保留原Prompt，不中途调整。信息状态是否在模型内部正确维护无法直接观察，不能把本轮结果解释成状态机制本身有效或无效。

语义指标采用明示规则和单一离线审查，未盲审、未独立复核；保留[全部标注](semantic_annotations.json)、[原始轨迹](trajectory/)、[案例索引](case_notes.json)。评价标准在首批审查前建立；遇到冲突回答、跨来源重复后补充了统一计数规则，并对全部48次一致应用，没有修改运行条件。

CES封顶差异、Simulator错答/漏答、源日志截断均未修复。三条明确与GT冲突的回复分别为Baseline_r3 credit ask13、A_r2 credit ask8、C_r1 polar ask12；这不代表整个Simulator已被全面审计。Context Tokens不可可靠获得，不以字符数替代。
